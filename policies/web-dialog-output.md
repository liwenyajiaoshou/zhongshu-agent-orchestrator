# 网页对话输出契约

## 目标

中枢在网页版 GPT 中默认面向 Owner 输出，而不是面向工程师写长篇分析。

> 先说“现在是什么情况、对你有什么影响、下一步做什么”，再生成施工方案文件和可复制提示词。

默认少解释推理过程，不把内部分析过程搬给用户。

## 1. 重要施工回复顶部固定展示

```text
【线程建议】
对话线程：继续 / 更换
Codex 线程：继续 / 更换

【执行建议】
推荐工具：Codex / Antigravity
推荐模型：
推荐推理等级：低 / 中 / 高
施工模式：普通施工 / 受约束自主调试 / 只读审计
是否需要 Owner 操作：否 / 是（只写最小动作）
```

要求：
- 放在回复靠前位置；
- 如果建议换线程，必须明确是哪一种线程；

## 2. 用户视角说明

施工卡片后只回答：
1. 现在做到哪了；
2. 当前真正影响推进的问题；
3. 对 Owner 的影响；
4. 下一步。

禁止默认输出长篇架构复述、内部推理过程、完整施工报告复述、完整测试日志、与当前阶段无关的边缘问题。

## 3. 下一步只给最小高收益动作

默认只推荐一个主动作；真正并列的必要动作最多 3 项。

## 4. 施工方案文件优先

需要 Codex / Antigravity 继续施工时：
- A 类：对话可给简短方案，也可生成文件；
- B 类：优先直接生成 Markdown 施工方案；
- C 类或长方案：必须生成 Markdown 文件，对话只给摘要和链接。

普通方案继续至少包含：task_goal、allowed_scope、forbidden_scope、required_tests、report_path，并说明 workspace / plan_path、推荐工具、模型与推理等级、线程建议、multi_agent、TUN、只读/可写、验收标准、Git/Network/Data/Release、stop conditions。

## 5. 同时提供可复制提示词

默认模板：

```text
请读取并严格执行：
<PLAN_PATH>

开工前先读取项目最新 AGENTS.md、规则索引和项目特定治理规则；冲突时以项目内最新且更严格规则为准。

按方案完成施工与测试，并将精简报告写入：
<REPORT_PATH>

遇到真实联网、外部 API、依赖下载、正式数据写入、生产资产/语义变化、不可逆 Git、发布、风险升级或需要 Owner 决策时停止并报告。

不要 commit / push / PR / tag / release，不执行 reset / clean / rebase / force。
```

受约束自主调试时追加：边界内允许连续诊断、修改、测试，不要每发现一个普通问题就返回 Owner；触碰 hard boundary 才停止。

## 6. 报告审计默认结构

```text
【施工结论】
PASS / REPAIR / PARTIAL / BLOCKED

【线程建议】
对话线程：
Codex 线程：

【施工质量】
施工质量：正常 / 需关注 / 明显不足
重复失败：否 / 是
推荐推理等级：
模型/推理提醒：仅在有证据时填写

【从你的角度看】
现在做到哪：
当前问题：
对你的影响：

【下一步】
<最小高收益动作>

【施工文件】
<若需继续施工则给 plan>

【给 Codex 的提示词】
<可直接复制>
```

## 7. 施工质量触发式模型提醒

正常施工不输出“模型胜任度”，也不无证据评价模型是否够用。

只有出现施工质量明显不足、重复失败或同类错误频发时，才触发模型 / 推理提醒；触发后先区分推理等级、上下文、规格、环境/工具、测试/数据、治理误阻塞、真实外部 blocker 与普通实现错误。只有中高置信证据支持时，才提示“疑似模型能力不足”。

## 8. 默认长度

- 普通审计：约 300～700 中文字；
- 简单 PASS：可以更短；
- 复杂 BLOCKED / 高风险：只增加必要解释；
- 详细技术分析写进施工方案/审计文档，不占聊天正文。

除非 Owner 明确要求详细分析，否则保持简洁、通俗、可执行。

## 9. 非目标

不建立新的报告系统、UI、状态数据库、模型评分平台或额外治理层。


---

## 10. 对话线程提醒

当阶段对话线程明显变长时，中枢需要主动判断是否出现上下文饱和。

不使用“50 次必须换”“100 次必须换”等硬阈值。

如果出现：
- 当前状态越来越难概括；
- 多个已关闭问题反复被重提；
- 每次都要重述大量旧背景；
- 当前任务只依赖最近少量上下文；
- 已跨多个 blocker / 子任务；
- 对话轮次已经非常长；

则应在回复靠前位置提示：

```text
对话线程：建议在当前局部任务收口后更换
原因：历史噪声已明显增加
```

如果新 blocker 已形成独立问题单元，则可以提示：

```text
对话线程：主阶段线程继续
问题处理对话线程：建议新开
```

问题处理线程闭环后，应压缩结果回填主阶段，不把完整讨论历史复制回来。
